## 1. نظرة عامة على المشروع وهندسة النظام

هذا المشروع عبارة عن منظومة متكاملة لبوابة التسجيل المحتجزة (**MikroTik Hotspot Captive Portal**) الخاصة بـ **شبكة الكاري نت اللاسلكية**. صُممت المنظومة لتخدم غرضين رئيسيين:

1. **العمل المباشر كنظام Hotspot كامل على أجهزة راوتر بورد مايكروتك (MikroTik RouterOS)** بجميع إصداراته (v6.x و v7.x).
2. **العمل كمحاكي ويب سحابي تفاعلي (Local Simulator & Dev Server)** مبني باستخدام بيئة **Node.js و Express**، مما يتيح معاينة القوالب، وتجربة تسجيل الدخول، وفحص عدادات الاستهلاك والوقت، وتصدير حزمة جاهزة للمايكروتك بنقرة زر واحدة دون الحاجة لوجود راوتر فعلي أثناء الاختبار والتطوير.

### الخصائص المعمارية الأساسية:
- **دعم تسجيل الدخول بنظام الكرت الموحد (Voucher Code):** حيث يكون اسم المستخدم هو نفسه كلمة المرور عبر ميزة النسخ التلقائي `copyTextValue()`.
- **التشفير الآمن عبر بروتوكول HTTP-CHAP:** استخدام مكتبة `md5.js` لتشفير كلمة المرور مع `chap-challenge` و `chap-id` قبل إرسالها إلى الراوتر، مع دعم التراجع التلقائي لـ HTTP-PAP إذا كان السيرفر معداً لذلك.
- **جدار حماية أمامي ضد الهجمات والتخمين (Brute-Force Blocker):** حظر مؤقت للمستخدم عند تجاوز عدد المحاولات الخاطئة (3 إلى 5 محاولات) لمدة محددة مع عداد تنازلي حي في صفحة `block.html`.
- **حفظ بيانات الدخول وتسهيل إعادة الاتصال:** عبر كوكيز المتصفح (`hotCookie.min.js`) مع منع التكرار اللانهائي في حال حدوث خطأ.
- **تنقية وتصحيح مدخلات المستخدم:** عبر `hotInImprover.min.js` لتحويل الأرقام العربية (٠١٢٣) إلى إنجليزية (0123) وإزالة المسافات التي تسبب فشل الدخول أثناء نسخ ولصق الكود.
- **لوحة بيانات حية للاستهلاك (`status.html`):** حساب فوري للوقت المستهلك، والوقت المتبقي، وحجم البيانات المستهلكة، والرصيد المتبقي بوحدات عربية ذكية (كيلوبايت، ميجابايت، جيجابايت).
- **تعريب شامل واحترافي لجميع رسائل وأخطاء المايكروتك:** عبر ملف `errors.txt` ومطابقات JavaScript داخل صفحة الدخول.
- **التوافق القياسي مع بروتوكول WISPr 1.0:** للتوافق مع مساعدات تسجيل الدخول في الهواتف الذكية (Android Captive Portal, Apple Captive Network Assistant CNA, Windows NCSI).

## 2. المقارنة الشاملة والدقيقة بين صفحة login.html ونسخة login - نسخة.html

يحتوي المشروع على نسختين أساسيتين لواجهة تسجيل الدخول؛ كل نسخة مصممة لتلائم سيناريوهات استخدام محددة وفق متطلبات الشبكة والأداء والوظائف المتقدمة:

### 📊 جدول المقارنة الفنية الشاملة:

| الميزة / المعيار الفني | الصفحة الأساسية (`login.html`) | النسخة المطورة (`‏‏login - نسخة.html`) |
| :--- | :--- | :--- |
| **هيكل الواجهة والإطار** | قالب كلاسيكي مبني على Bootstrap 3 مخصص مع جداول أسعار مدمجة | قالب حديث متجاوب بتصميم كروت عائمة مع خط المراعي وأيقونات Fontello |
| **آلية إدخال الكرت** | حقل إدخال واحد مع دالة `copyTextValue()` لنسخ الاسم إلى كلمة المرور | حقل إدخال كرت ذكي مزود بمحرك التنقية `hotInImprover` |
| **نظام التحكم بالسرعات (Speed/Domain)** | سرعة ثابتة يحددها الراوتر عبر البروفايل التلقائي | قائمة منسدلة (`<select name="domain">`) تتيح للعميل اختيار سرعة (512K أو 100M) |
| **حماية التخمين والحظر (hotBlocker)** | تعتمد فقط على الرد المباشر من المايكروتك | مدمجة بمحرك `hotBlocker.min.js` لحظر المتصفح بعد 3 محاولات خاطئة والتحويل لـ `block.html` |
| **إدارة الكوكيز والحفظ (hotCookie)** | غير مدمجة (يتطلب إدخال الكرت يدوياً في كل زيارة) | مدمجة بمحرك `hotCookie.min.js` وزر تبديل (iOS Toggle) لتذكر الكرت تلقائياً |
| **معالجة وتصحيح المدخلات (hotInImprover)** | الإدخال كما يكتبه العميل بدون معالجة مسبقة | تحويل فوري للأرقام العربية (٠-٩) إلى إنجليزية وحذف المسافات البيضاء تلقائياً |
| **الوضع الليلي (Dark Mode)** | الوضع النهاري القياسي فقط | زر تبديل فوري للوضع الليلي/النهاري مع حفظ الحالة في `localStorage` |
| **الشريط الإخباري المتحرك** | غير موجود | شريط إخباري علوي متحرك (`<marquee>`) مع أيقونة تنبيه متحركة `new.gif` |
| **النوافذ المنبثقة التفاعلية (Modals)** | لا توجد نوافذ منبثقة (المعلومات معروضة مباشرة في الصفحة) | نوافذ منبثقة منسدلة عبر `label.js` لأرقام الدعم، ونقاط البيع، والأسعار، واتصل بنا |
| **تشفير كلمات المرور (CHAP / PAP)** | مدعوم بالكامل عبر `md5.js` | مدعوم بالكامل عبر `md5.js` مع تكامل مع `hotBlocker` |
| **حجم الصفحة والاعتماديات** | خفيفة جداً، وسريعة الفتح على أجهزة الراوتر القديمة | غنية بالميزات التفاعلية، ومناسبة للشبكات التجارية الكبرى |

### 🛠 تفصيل جوانب الربط والوظائف البرمجية:
1. **الربط والمصادقة:**
   * في `login.html`: يتم التحقق البسيط عبر إرسال النموذج `sendin` المشفر بـ MD5 إلى `$(link-login-only)`.
   * في `login - نسخة.html`: يتم تنفيذ دورة فحص ثلاثية قبل الإرسال (فحص الحظر `hotBlocker` -> تنقية الرمز `hotInImprover` -> حفظ الكوكيز `hotCookie` -> ثم التشفير والإرسال).
2. **التحكم بالباندويث:**
   * النسخة المطورة ترسل المتغير `domain=512K/512K` أو `domain=100M/100M` مما يتيح للمايكروتك توجيه المستخدم لبروفايل سرعة محدد عبر سكربت `on-login`.
3. **تجربة المستخدم (UX):**
   * النسخة الكلاسيكية تفيد الأجهزة الضعيفة والأماكن ذات التغطية المنخفضة لصغر حجمها.
   * النسخة المطورة تقدم تجربة شبيهة بالتطبيقات الحديثة مع التبديل الليلي وتجنب أخطاء لوحة المفاتيح.

## 4. الفحص الشامل والدقيق لكل ملف ومجلد في المنظومة

### أ. ملفات البوابة الأساسية (Root Pages):

| الملف | الوظيفة الدقيقة والخصائص التقنية |
| :--- | :--- |
| **`login.html`** | الصفحة الرئيسية المعروضة للمستخدم عند محاولة تصفح الإنترنت. تدعم حقل كرت واحد يُنسخ تلقائياً لكلمة المرور `copyTextValue()`، وتتعرف على استجابة الراوتر وتشفير CHAP/PAP، وتحتوي على جدول أسعار الكروت (100، 300، 500، 1000، 2500 ريال)، وأرقام نقاط البيع وخدمة العملاء. |
| **`‏‏login - نسخة.html`** | نسخة متطورة ومميزة من صفحة الدخول تضم: قائمة منسدلة لاختيار السرعة (`<select name="domain">` بين 512K و 100M)، وزر تفعيل الوضع الليلي (Dark Mode) المخزن محلياً في `localStorage`، والربط مع سكربت الحظر `hotBlocker` والحفظ `hotCookie` وتنقية الإدخال `hotInImprover`، وشريط إخباري متحرك، ونوافذ منبثقة للاتصال والوكلاء. |
| **`status.html`** | صفحة لوحة التحكم التي يراها المشترك بعد فتح الإنترنت. تعرض ساعة عربية متزامنة، والوقت المستهلك `$(uptime)`، والوقت المتبقي للجلسة `$(session-time-left)`، وحجم التنزيل والرفع المحول لعربيات القياس `readablizeBytes($(bytes-total))`، والرصيد المتبقي `$(remain-bytes-total)`، وزر تسجيل الخروج مع مسح الكوكيز. |
| **`logout.html`** | صفحة إشعار انتهاء الجلسة. تظهر جدولاً يحتوي على إحصائيات الجلسة المغلقة: اسم المشترك، عنوان IP وعنوان MAC، والمدة المستهلكة، وحجم البايتات المتبادلة عبر `$(bytes-in-nice)` و `$(bytes-out-nice)`، مع زر العودة لصفحة الدخول. |
| **`block.html`** | تظهر للعميل إذا تجاوز عدد المحاولات الخاطئة المحددة في `hotBlocker.min.js`. تعرض رسالة: *"لقد تم حظرك بسبب محاولات تسجيل الدخول الكثيرة الخاطئة"*، مع عداد تنازلي حي يحسب الدقائق والثواني المتبقية ويفك الحظر تلقائياً. |
| **`alogin.html`** | صفحة وسيطة تنقل المستخدم فور إتمام المصادقة بنجاح إلى صفحة `status.html` وتفتح نافذة منبثقة مصغرة لمتابعة الرصيد في حال كان خيار `$(popup)` مفعل في الراوتر. |
| **`rlogin.html`** | صفحة إعادة التوجيه لبروتوكول WISPr، تحتوي على رأس XML مخفي يتعرف عليه نظام أندرويد وiOS لتسجيل الدخول التلقائي وفتح المتصفح النظامي. |
| **`redirect.html`** | تعيد توجيه المشترك إلى الموقع الأصلي الذي كان يطلبه قبل اعتراضه من قبل البوابة عبر المتغير `$(link-redirect)`. |
| **`radvert.html`** | تدير الإعلانات الترويجية للشبكة في نافذة منبثقة بمجرد الاتصال إذا كانت مفعلة في خيارات سيرفر المايكروتك `advert-pending`. |
| **`error.html`** | صفحة بديلة خفيفة الوزن تظهر للمستخدم إذا فشل الاتصال مع توضيح سبب الخطأ عبر المتغير `$(error)`. |
| **`prices.html`** | صفحة استعراض أسعار الباقات بتصميم عصري (Glassmorphism / Cards) متوافقة مع شاشات الهواتف مع زر عودة للبوابة الرئيسية. |
| **`errors.txt`** | ملف نصي خاص بالمايكروتك يقوم بترجمة رسائل الخطأ الداخلية الصادرة عن RouterOS إلى اللغة العربية الفصحى المبسطة قبل إرسالها إلى المتصفح. |
| **`api.json`** | ملف يعيد كائن JSON متوافق مع مواصفة IETF RFC 8952 لتطبيقات الهواتف الذكية لمعرفة هل المستخدم محتجز (Captive)، ورابط تسجيل الدخول، والرصيد المتبقي بالثواني والبايتات. |
| **`md5.js`** | تطبيق جافا سكريبت لخوارزمية RFC 1321 لتوليد التجزئة الأمنية للمصادقة المشفرة بنمط CHAP. |

## 5. آلية الربط مع سيرفر المايكروتك ومتغيرات النظام (MikroTik Variables)

يقوم محرك الـ Hotspot في نظام MikroTik RouterOS باستبدال العلامات البرمجية التي تبدأ بـ `$(...)` بالقيم الحقيقية للعميل أثناء تمرير الصفحات. المنظومة الحالية تعتمد على مجموعة دقيقة من المتغيرات:

### جدول المتغيرات المستخدمة في صفحات المشروع:

| المتغير البرمجي | الصفحة المستخدم فيها | الوصف الفني وقيمته في المايكروتك |
| :--- | :--- | :--- |
| `$(link-login-only)` | `login.html`, `login - نسخة.html` | رابط المعالج الداخلي في المايكروتك المسؤول عن استقبال بيانات النموذج (مثلاً: `http://192.168.88.1/login`). |
| `$(link-login)` | `logout.html`, `error.html`, `prices.html` | الرابط المؤدي لصفحة تسجيل الدخول الأساسية. |
| `$(link-logout)` | `status.html`, `logout.html` | الرابط المسؤول عن قطع جلسة العميل في السيرفر وتفريغ جداول الـ Active. |
| `$(link-status)` | `login.html`, `alogin.html`, `prices.html` | رابط صفحة الحالة لمتابعة الاستهلاك والرصيد. |
| `$(link-orig)` | `login.html`, `radvert.html` | الموقع الأصلي الذي طلبه المشترك قبل اعتراض اتصاله (مثل `http://google.com`). |
| `$(link-redirect)` | `redirect.html`, `alogin.html` | رابط التوجيه النهائي للعميل بعد تمام المصادقة. |
| `$(username)` | `login.html`, `status.html`, `logout.html` | اسم المستخدم المسجل أو المراد دخوله. |
| `$(password)` | `login.html` | كلمة المرور المشفرة أو الصريحة. |
| `$(ip)` | `logout.html`, `errors.txt` | عنوان IP المخصص لجهاز العميل من حزمة الـ DHCP Pool. |
| `$(mac)` | `logout.html`, `status.html` | العنوان الفيزيائي لكرت شبكة العميل (MAC Address). |
| `$(uptime)` | `status.html`, `logout.html` | المدة الزمنية النشطة التي قضاها العميل في هذه الجلسة (ساعات/دقائق/ثواني). |
| `$(session-time-left)` | `status.html`, `logout.html`, `api.json` | الوقت المتبقي لحساب العميل قبل قطع الاتصال. |
| `$(bytes-total)` | `status.html` | إجمالي البايتات المستهلكة في الجلسة الحالية (رفع + تنزيل). |
| `$(remain-bytes-total)`| `status.html`, `api.json` | رصيد التحميل المتبقي للكرت بالبايت في حال كانت الباقة محددة بحجم كوته. |
| `$(bytes-in-nice)` | `logout.html` | حجم البيانات المستلمة بصيغة سهلة القراءة (مثل `14.2 MB`). |
| `$(bytes-out-nice)` | `logout.html` | حجم البيانات المرسلة بصيغة سهلة القراءة. |
| `$(chap-id)` | `login.html`, `‏‏login - نسخة.html` | المعرف العشوائي المشترك المولد من السيرفر لكل محاولة لتأمين التشفير. |
| `$(chap-challenge)` | `login.html`, `‏‏login - نسخة.html` | التحدي العشوائي المشفر المطلوب دمجه مع كلمة المرور لمنع هجمات التكرار (Replay Attacks). |
| `$(error)` | `login.html`, `error.html`, `block.html` | نص رسالة الخطأ القادمة من المايكروتك عند فشل محاولة الدخول. |
| `$(refresh-timeout-secs)` | `status.html` | مهلة التحديث التلقائي لصفحة الحالة بالثواني المحددة في بروفايل الهوتبوت. |

### الجمل الشرطية المستخدمة (Conditional Tags):
- `$(if chap-id)...$(endif)`: لتفعيل نموذج المصادقة المشفر في حال كان الهوتبوت يدعم CHAP.
- `$(if error)...$(endif)`: لعرض صندوق التنبيهات والأخطاء باللغة العربية عند وجود خطأ.
- `$(if session-time-left)...$(endif)`: لعرض عداد الوقت المتبقي فقط إذا كان الحساب مقيداً بوقت.
- `$(if logged-in == 'yes')...$(else)...$(endif)`: للتحقق من حالة اتصال المستخدم في ملفات API والمحاكي.

## 6. دورة حياة تسجيل الدخول والمصادقة (CHAP vs PAP)

```text
[المشترك] ─── طلب موقع خارجي ───► [راوتر المايكروتك]
                                         │
                                   (اعتراض الاتصال)
                                         ▼
[المشترك] ◄─── عرض صفحة login.html ──────┘
    │
    ├── ادخال الكرت (اسم المستخدم)
    ├── دالة copyTextValue() تنسخ الكرت إلى حقل كلمة المرور المخفي
    │
    ├── إذا كان CHAP مفعلاً في السيرفر:
    │     استدعاء دالة doLogin()
    │     تشفير: hexMD5(chap_id + password + chap_challenge)
    │     إرسال الطلب عبر نموذج sendin إلى $(link-login-only)
    │
    └── إذا كان PAP مفعلاً:
          إرسال اسم المستخدم وكلمة المرور مباشرة عبر POST
                                         │
                                         ▼
                               [تحقق الراوتر / Radius]
                                ┌────────┴────────┐
                                ▼                 ▼
                           [نجاح الدخول]     [فشل الدخول]
                                │                 │
                       توجيه المشترك إلى    توجيه إلى login.html
                       alogin.html ومنها    مع كود $(error)
                       إلى status.html      وتسجيل محاولة فاشلة في
                       لتصفح الإنترنت       hotBlocker لحساب الحظر
```

### تفاصيل دوال المصادقة في ملفات المشروع:
1. **دالة النسخ التلقائي للكرت:**
   ```javascript
   function copyTextValue() {
     var text1 = document.getElementById("username").value;
     document.getElementById("password").value = text1;
   }
   ```
2. **دالة المصادقة المشفرة (CHAP Authentication):**
   ```javascript
   function doLogin() {
     document.sendin.username.value = document.login.username.value;
     document.sendin.password.value = hexMD5('$(chap-id)' + document.login.password.value + '$(chap-challenge)');
     document.sendin.submit();
     return false;
   }
   ```

## 7. إعدادات السرعات واختيار الباقات وتوزيع الباندويث (Speed Control)

### أ. كيف يعمل اختيار السرعة في واجهة البوابة (`‏‏login - نسخة.html`):
تحتوي النسخة المتقدمة من صفحة الدخول على عنصر اختيار سرعة للمستخدم قبل الضغط على دخول:
```html
<select name="domain">
    <option value="512K/512K">سرعة ضعيفة</option>
    <option value="100M/100M" selected>سرعة قوية</option>
</select>
```
كما يوجد حقل مخفي مخصص للسرعة:
```html
<input type="hidden" name="speed" value="false" />
```

### ب. كيف يستقبل سيرفر المايكروتك هذه القيمة ويطبق السرعة:
في نظام MikroTik Hotspot:
1. عند إرسال معامل `domain` في نموذج الدخول، يقوم المايكروتك بربط المستخدم بـ **Hotspot User Profile** الذي يحمل نفس النطاق (Domain) أو استخدامها في خادم الـ RADIUS (User-Name = `user@domain`).
2. يمكن لمهندس الشبكة ضبط بروفايلات المستخدمين في المايكروتك لتحديد السرعات (Rate Limit / Rx Tx) كالتالي:

```routeros
# إنشاء بروفايل للسرعة العادية / الضعيفة (512 كيلوبت)
/ip hotspot user profile
add name="speed-512k" rate-limit="512k/512k" shared-users=1

# إنشاء بروفايل للسرعة الفائقة / القوية ( مفتوحة أو محددة بـ 20 ميجا )
/ip hotspot user profile
add name="speed-strong" rate-limit="10M/20M" shared-users=1
```

3. **سكربت مايكروتك تلقائي لتطبيق السرعة فور تسجيل دخول المستخدم:**
في المايكروتك ضمن `/ip hotspot user profile`:
في خانة **on-login**:
```routeros
:local uname "$user";
:local speed [/ip hotspot active get [find user=$uname] domain];
:if ($speed = "512K/512K") do={
    /queue simple set [find name=("<hotspot-" . $uname . ">")] max-limit=512k/512k
} else={
    /queue simple set [find name=("<hotspot-" . $uname . ">")] max-limit=10M/50M
}
```

## 8. إيقاف التحديثات الإجبارية (Windows, Android, iOS Updates Blocking)

من خلال فحص جميع ملفات المشروع البرمجية بدقة، نجد أن:
- **المتصفحات وملفات HTML/JS لا تستطيع من جانب العميل إيقاف تحديثات نظام التشغيل ويندوز أو أندرويد** لأن التحديثات تعمل كخدمات نظام خلفية (System Services).
- إن الطريقة الهندسية الوحيدة والصحيحة المعتمدة لدى مهندسي شبكات المايكروتك لمنع استنزاف رصيد وباندويث الشبكة هي تطبيق **قواعد جدار الحماية (Firewall Filter Rules) وقوائم العناوين (Address Lists) في الراوتر نفسه**.

إليك سكربت المايكروتك الكامل الذي يجب إضافته في التيرمنال لحظر تحديثات الويندوز، ومتجر جوجل، وآبل لعملاء الهوتبوت:

```routeros
###################################################################
# سكربت مايكروتك لإيقاف تحديثات Windows و Google Play و Apple iOS
###################################################################

# 1. إنشاء قائمة نطاقات التحديثات في DNS والـ Firewall
/ip firewall address-list
add list=UPDATE_DOMAINS address=windowsupdate.microsoft.com
add list=UPDATE_DOMAINS address=update.microsoft.com
add list=UPDATE_DOMAINS address=download.windowsupdate.com
add list=UPDATE_DOMAINS address=wustat.windows.com
add list=UPDATE_DOMAINS address=ntservicepack.microsoft.com
add list=UPDATE_DOMAINS address=stats.update.microsoft.com
add list=UPDATE_DOMAINS address=play.google.com
add list=UPDATE_DOMAINS address=android.clients.google.com
add list=UPDATE_DOMAINS address=appldnld.apple.com
add list=UPDATE_DOMAINS address=mesu.apple.com
add list=UPDATE_DOMAINS address=swscan.apple.com

# 2. حظر منافذ خدمة التحديث بالـ Raw لتقليل استهلاك المعالج (CPU)
/ip firewall raw
add chain=prerouting action=drop protocol=tcp dst-port=8530,8531 comment="Block Windows WSUS Update Ports"
add chain=prerouting action=drop dst-address-list=UPDATE_DOMAINS comment="Drop Traffic to Update Servers"

# 3. حظر أسماء النطاقات عبر فحص حزم TLS Host (Layer 7 / TLS SNI)
/ip firewall filter
add chain=forward action=drop protocol=tcp dst-port=443 tls-host="*windowsupdate*" comment="Block Windows Updates HTTPS"
add chain=forward action=drop protocol=tcp dst-port=443 tls-host="*update.microsoft*" comment="Block Microsoft Updates"
add chain=forward action=drop protocol=tcp dst-port=443 tls-host="*swcdn.apple.com*" comment="Block Apple Updates"
```

## 9. نظام الحماية والحظر التلقائي ضد التخمين (hotBlocker)

يتحكم في نظام الحظر ملف `assets/js/hotBlocker.min.js` المرتبط بصفحة `block.html`.

### آلية عمل نظام الحظر:
1. يتم تضمين السكربت في صفحة الدخول بالصيغة التالية:
   ```html
   <script src="assets/js/hotBlocker.min.js" login-error="$(error)" try-count="3" block-time="1"></script>
   ```
   - **`try-count="3"`**: أقصى عدد محاولات دخول خاطئة مسموح بها للمتصفح (افتراضياً 3 إلى 5).
   - **`block-time="1"`**: مدة الحظر بالدقائق (في الكود أعلاه: دقيقة واحدة).
   - **`login-error="$(error)"`**: يراقب هل أرجع المايكروتك رسالة خطأ بعد المحاولة.

2. **الكوكيز المستخدمة في الحظر:**
   - `hot_blocker_counter`: عداد المحاولات الفاشلة للمستخدم.
   - `hot_blocker_blocked_time`: الطابع الزمني (Timestamp) لوقت بدء تطبيق الحظر.
   - `hot_blocker_block_minutes`: عدد دقائق الحظر المحددة.

3. **سلوك النظام عند تجاوز المحاولات:**
   - يقوم السكربت بضبط الكوكيز وتحويل المتصفح فوراً إلى `block.html`.
   - في صفحة `block.html`، يتم استدعاء العداد التنازلي:
     ```html
     <span count-down-span></span>
     ```
     حيث يظهر للمستخدم: `يتبقى X دقائق و Y ثانية`.
   - عند وصول العداد إلى الصفر، يتم مسح كوكيز الحظر تلقائياً وإعادة توجيه المستخدم لصفحة `login.html`.
   - عند تسجيل الدخول بنجاح، يستشعر السكربت السمة `clear-hot-blocker` ويقوم بتصفير العداد فوراً.

## 10. إدارة الكوكيز والحفظ التلقائي للحساب (hotCookie & Remember Me)

يتحكم في هذا النظام السكربت `assets/js/hotCookie.min.js`.

### كيفية حفظ الحساب وإعادة تسجيل الدخول التلقائي:
1. **خيار "تذكرني" في واجهة المستخدم:**
   ```html
   <input type="checkbox" name="checkbox1" id="remember" class="ios-toggle" value="ON" checked />
   ```
2. **عند الضغط على تسجيل الدخول (`rem()`):**
   - إذا كان خيار `remember` مفعلاً، يتم حفظ اسم المستخدم وكلمة المرور في كوكيز المتصفح:
     - كوكيز `uname`: اسم المستخدم (صالحة لمدة 3 أيام = 259,200 ثانية).
     - كوكيز `paswd`: كلمة المرور (صالحة لمدة 3 أيام).
     - كوكيز `error`: لتسجيل وجود أي خطأ مؤقت لمدة 5 ثوانٍ فقط.
3. **عند عودة المستخدم للصفحة مجدداً (`getCookie()`):**
   - يقرأ السكربت المتصفح تلقائياً فور تحميل الصفحة.
   - إذا وجد الكوكيز `uname` و `paswd` محفوظة، ولم يكن هناك خطأ نشط، يقوم بتوجيه المتصفح تلقائياً:
     ```javascript
     window.location.href = 'login?username=' + uname + '&password=' + paswd;
     ```
   - هذا يمنح المشترك تجربة تسجيل دخول سلسة وسريعة دون إعادة كتابة رقم الكرت في كل مرة.

## 11. نظام تحسين ومعالجة نصوص الإدخال (hotInImprover)

يتحكم في هذا النظام السكربت `assets/js/hotInImprover.min.js`. صُمم هذا النظام خصيصاً لحل المشاكل الشائعة التي تواجه المشتركين عند كتابة أرقام الكروت:

### القدرات والسمات البرمجية المدعومة:
عند وضع السمة `improve-input` على أي حقل نصي، يمكن تزويده بالسمات التالية:
- **`rm-white-spaces`**: إزالة جميع الفراغات والمسافات تلقائياً (تمنع خطأ نسخ الكرت مع مسافة في البداية أو النهاية).
- **`to-arabic-numbers`**: تصحيح الأرقام الهندية/العربية (٠١٢٣٤٥٦٧٨٩) وتحويلها الفوري إلى أرقام لاتينية قياسية (0123456789).
- **`to-lower`**: تحويل الأحرف اللاتينية إلى صغيرة (Lowercase).
- **`to-upper`**: تحويل الأحرف إلى كبيرة (Uppercase).
- **`only-numbers`**: حصر الحقل على الأرقام فقط وحذف أي رمز أو حرف.
- **`only-alphanumeric`**: السماح فقط بالحروف والأرقام وإلغاء الرموز الخاصة.

## 12. الرسائل والأخطاء القادمة من المايكروتك وقاموس التعريب (Error Handling)

تم تجهيز المنظومة بمستويين من التعريب:
1. تعريب السيرفر الأصلي عبر ملف `errors.txt` المعتمد من RouterOS.
2. فحص الجافا سكريبت في الواجهة الأمامية لاستبدال أي رسالة إنجليزية برسالة عربية واضحة ومريحة للمشترك.

### جدول مطابقات رسائل الخطأ:

| رسالة المايكروتك الأصلية (`$(error)`) | المعنى الفني للخطأ | الرسالة العربية المعروضة للمشترك في البوابة |
| :--- | :--- | :--- |
| `simultaneous session limit reached` | الكرت مسجل دخول حالياً في جهاز آخر | **"المعذرة ، هذا الحساب مستخدم حالياً في جهاز آخر"** |
| `invalid username or password` | خطأ في كتابة رقم الكرت أو كلمة المرور | **"خطأ في كلمة المرور أو اسم المستخدم"** |
| `invalid password` | كلمة المرور غير صحيحة | **"تأكد من كتابة كلمة المرور بشكل صحيح"** |
| `uptime limit reached` | انتهت ساعات العمل المتاحة للكرت | **"عذراً لقد انتهى الوقت المتاح لك.."** |
| `user $(username) has reached traffic limit` | استنفاد رصيد التحميل أو الجيجابايت | **"لقد انتهى رصيد تحميل هذا الحساب"** |
| `no valid profile found` | انتهاء الصلاحية الزمنية للكرت (مثلاً بعد 10 أيام) | **"لقد انتهت صلاحية هذا الحساب."** |
| `not found` | رقم الكرت غير مسجل أصلاً في قاعدة بيانات الراوتر | **"لقد ادخلت اسم المستخدم بطريقة غير صحيحة، الرجاء المحاولة مرة أخرى"** |
| `invalid Calling-Station-Id` | الكرت مقترن بعنوان MAC لجهاز آخر (Lock to MAC) | **"هذا الحساب مقترن بجهاز آخر، لمزيد من المعلومات يرجى الاتصال بخدمة العملاء"** |
| `user is not allowed to log in from this MAC` | منع الدخول من هذا العنوان الفيزيائي | **"هذا الحساب مقترن بجهاز آخر"** |
| `radius timeout` | عدم استجابة سيرفر الـ Radius (مثل يوزر مانجر خارجي) | **"عزيزي المشترك نعتذر عن انقطاع الخدمة بسبب الصيانة"** |
| `ippool-empty` | نفاد عناوين الـ IP المتاحة في السيرفر | **"لا يوجد مكان خالي على الشبكة حالياً، فضلاً عاود المحاولة في وقت لاحق"** |
| `shutting-down` | الراوتر في حالة إعادة تشغيل أو إيقاف | **"لا يمكن تسجيل الدخول الآن، حاول بعد قليل"** |
| `chap-missing` | تعطيل الجافا سكريبت أو انتهاء صلاحية جلسة التحدي | **"تأكد من إعدادات الجافا سكريبت في المتصفح الخاص بك، أو اتصل بإدارة الشبكة"** |

## 13. لوحة متابعة الرصيد والحالة والوقت المستهلك (Status Dashboard)

تعتبر صفحة `status.html` لوحة تحكم حية متطورة، وتحتوي على الميزات التالية:

1. **الساعة الذكية المتزامنة:**
   دالة `refrClock()` التي تعرض التاريخ بالأسماء العربية للأيام (السبت، الأحد، ...) والشهور (يناير، فبراير، ...) مع صيغة 12 ساعة بنظام صباحاً ومساءً وتحديث كل ثانية.

2. **تحويل البايتات إلى وحدات عربية مقروءة:**
   ```javascript
   function readablizeBytes(bytes) {
     var s = ['بايت', 'كيلوبايت', 'ميجابايت', 'جيجابايت', 'تيرابايت', 'PB'];
     var e = Math.floor(Math.log(bytes) / Math.log(1024));
     return (bytes / Math.pow(1024, Math.floor(e))).toFixed(2) + " " + s[e];
   }
   ```

3. **تعريب عداد الوقت المتبقي (`$(session-time-left)`):**
   يقوم كود الجافا سكريبت باستبدال الاختصارات الإنجليزية بالألفاظ العربية:
   ```javascript
   document.getElementById("timeLeft").innerHTML = "$(session-time-left)"
     .replace("w", " أسبوع , ")
     .replace("d", " يوم , ")
     .replace("h", " ساعة , ")
     .replace("m", " دقيقة , ")
     .replace("s", " ثانية");
   ```

4. **التحديث الدوري التلقائي (Auto Refresh):**
   ```html
   <meta http-equiv="refresh" content="$(refresh-timeout-secs)">
   ```
   يقوم المتصفح بإعادة تحميل الصفحة كل فترة زمنية لتحديث إحصائيات البيانات المستهلكة فوراً من الراوتر.

## 14. تسجيل الخروج وقطع الاتصال ومسح الجلسة (Logout & Disconnect)

### أ. في صفحة الحالة (`status.html`):
يتم إنهاء الجلسة عبر نموذج خروج يرسل أمراً إلى `$(link-logout)` مع مسح الكوكيز المسجلة:
```html
<form action="$(link-logout)" name="logout" onSubmit="return openLogout()">
    <input type="hidden" name="erase-cookie" value="on">
    <button type="submit">تسجيل الخروج</button>
</form>
```
- إرسال `erase-cookie=on` يضمن أن يقوم المايكروتك بإلغاء ارتباط عنوان الماك (MAC Cookie) لكي يطلب من المستخدم تسجيل الدخول مجدداً ولا يدخله تلقائياً بدون كرت.

### ب. في صفحة الخروج (`logout.html`):
تستقبل الصفحة بيانات الجلسة المنتهية وتعرض للمشترك ملخصاً كاملاً:
- اسم الحساب.
- عنوان الـ IP والـ MAC.
- وقت الجلسة الفعلي.
- كمية البيانات المحملة والمرفوعة.
- زر لإعادة تسجيل الدخول فوراً عبر الرابط `$(link-login)`.

## 15. بروتوكول التجوال الذكي وملفات الـ XML (WISPr Access Gateway)

يحتوي مجلد `xml/` على بنية متكاملة لبروتوكول **WISPr 1.0 (Wireless Internet Service Provider roaming)**. 

### ما فائدة هذه الملفات؟
- تتيح للهواتف الذكية (مثل ميزة Captive Portal Detection في Android وأنظمة Apple iOS و macOS و Windows 10/11) التعرف الذكي على الشبكة وفتح متصفح النظام المنبثق فور الاتصال بالواي فاي بدون الحاجة لقيام المستخدم بفتح المتصفح يدوياً.
- **ملف `xml/WISPAccessGatewayParam.xsd`:** المخطط القياسي الذي يحدد هياكل رسائل المصادقة وتوجيه العميل.
- **كود الردود القياسية المستخدمة:**
  - `MessageType 100`: إشعار التوجيه لبوابة تسجيل الدخول (Initial Redirection).
  - `MessageType 120`: رد المصادقة (Authentication Reply).
  - `ResponseCode 50`: نجاح تسجيل الدخول (Login Succeeded).
  - `ResponseCode 100 / 102`: خطأ في البيانات أو مهلة السيرفر.
  - `ResponseCode 150`: نجاح تسجيل الخروج (Logoff Reply).
  - `ResponseCode 255`: خطأ في البوابة (Gateway Error).
- دعم تمرير حقول الـ RADIUS الخاصة بالمشتركين: `$(radius18[0])` إلى `$(radius18[4])`.

## 16. محاكي التطوير المحلي وخادم Node.js Express

تم بناء خادم المحاكاة `server.js` لتسهيل فحص وتطوير صفحات الهوتبوت محلياً دون الحاجة لراوتر:

### أبرز ميزات خادم المحاكاة:
1. **محرك معالجة قوالب المايكروتك (`renderMikrotikTemplate`):**
   يقوم بمعالجة جميع المتغيرات والكتل الشرطية `$(if ...)...$(endif)` وإرجاع شفرة HTML نقية وصحيحة للمتصفح.
2. **محاكاة ديناميكية للاستهلاك:**
   عند عمل تسجيل دخول عبر السيرفر:
   - ينشئ جلسة كوكيز `hotspot_session`.
   - يقوم بزيادة حجم التحميل بمعدل 15 كيلوبايت/ثانية، والرفع بمعدل 3 كيلوبايت/ثانية بصورة حية لمحاكاة استهلاك العميل الحقيقي.
   - يخصم البيانات المستهلكة من الرصيد الإجمالي للكرت.
3. **توليد وتحميل حزمة المايكروتك بنقرة واحدة:**
   يوفر الخادم مساراً خاصاً:
   ```http
   GET /api/download-hotspot
   ```
   يقوم بضغط جميع ملفات القالب والمجلدات في ملف مضغوط `alkary-mikrotik-hotspot.zip` جاهز ومعد للرفع المباشر إلى الراوتر.

### تشغيل الخادم محلياً:
```bash
# تثبيت الحزم المطلوبة
npm install

# تشغيل خادم المحاكاة
npm start
```
سيعمل المحاكي على الرابط: `http://localhost:3000`

## 17. دليل التركيب والرفع المباشر على راوتر المايكروتك خطوة بخطوة

لتركيب وتفعيل هذه الصفحات على شبكة المايكروتك:

### الخطوة الأولى: تجهيز الملفات
1. تأكد من تحميل مجلد المشروع بجميع ملفاته الأساسية (`login.html`, `status.html`, `logout.html`, `errors.txt`, `assets`, `css`, `fonts`, `images`, `img`, `xml`).
*(لا تقم برفع `server.js` أو `package.json` أو `node_modules` إلى الراوتر لأنها مخصصة لمحاكي التطوير فقط)*.

### الخطوة الثانية: الرفع إلى الراوتر عبر برنامج Winbox أو FTP
1. افتح برنامج **Winbox** وسجل الدخول إلى الراوتر بصلاحيات مدير (Admin).
2. افتح قائمة **Files** من القائمة الجانبية.
3. قم بسحب وإسقاط المجلد في قائمة الملفات، ويفضل أن يكون في مسار `hotspot` أو مسار مخصص مثل `hotspot-alkary`.

### الخطوة الثالثة: تفعيل القالب في خادم الـ Hotspot
1. في Winbox، توجه إلى: **IP** -> **Hotspot**.
2. اختر علامة التبويب **Server Profiles**.
3. افتح البروفايل الخاص بالسيرفر (مثلاً `hsprof1`).
4. في خانة **HTML Directory**، اختر المجلد الذي قمت برفعه (مثل `hotspot`).
5. في علامة تبويب **Login**:
   - تأكد من تفعيل: **HTTP PAP** و **HTTP CHAP**.
   - فعّل خيار **MAC Cookie** إذا كنت ترغب بتذكر المستخدمين عبر أجهزتهم.
6. اضغط **Apply** ثم **OK**.

## 18. جدول استكشاف الأخطاء الشائعة وحلولها السريعة (Troubleshooting)

| المشكلة | السبب الفني المحتمل | الحل الموصى به |
| :--- | :--- | :--- |
| **ظهور رسالة "chap-missing" عند تسجيل الدخول** | الجافا سكريبت معطلة في المتصفح أو أن خيار HTTP-CHAP غير مفعل في المايكروتك | تأكد من تفعيل `HTTP CHAP` في `IP -> Hotspot -> Server Profiles -> Login`، وتأكد من رفع ملف `md5.js` في المسار الرئيسي للراوتر. |
| **الكود لا يقبل تسجيل الدخول وتظهر رسالة خطأ** | نسخ الكود مصحوباً بمسافات فارغة أو مكتوباً بأرقام عربية غير مدعومة | استخدام النسخة المطورة من صفحة الدخول المدمج بها سكربت `hotInImprover.min.js` لمعالجة الأرقام والمسافات تلقائياً. |
| **المستخدم محظور مؤقتاً في صفحة block.html** | تجاوز المشترك عدد المحاولات الخاطئة في التخمين | الانتظار حتى انتهاء مدة العداد التنازلي، أو مسح كوكيز المتصفح (`hot_blocker_*`) لفك الحظر فوراً. |
| **صفحة الحالة لا تظهر الوقت المتبقي** | حساب المشترك في الراوتر غير مقيد بوقت محدد (`limit-uptime`) | ضبط خيار `Limit Uptime` أو `Limit Bytes Total` في بروفايل المستخدم داخل المايكروتك لكي تظهر العدادات. |
| **الحروف العربية تظهر مشوهة (رموز غير مفهومة)** | اختلاف ترميز الصفحة في بعض المتصفحات القديمة | تم ضبط ترويسات الصفحات بترميز `utf-8` وترميز `windows-1256` لضمان التوافقية التامة مع جميع الأجهزة. |
| **العميل يخرج تلقائياً بدون طلب** | انتهاء مهلة الخمول (Idle Timeout) أو مهلة الجلسة | ضبط `Idle Timeout` و `Keepalive Timeout` في `Server Profiles` إلى مدة مناسبة (مثلاً 10 إلى 30 دقيقة). |
